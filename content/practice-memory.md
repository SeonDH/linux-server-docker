# [실습] 메모리 부족과 오류 확인 - 15분

> **실습 환경:** 호스트 Bash. Windows는 WSL Ubuntu, macOS는 터미널에서 실행한다.
> **준비:** Docker Desktop 실행 및 0장 완료.

## 메모리가 부족하면 어떻게 될까요? {#memory-limit-demo}
**비교 실습 · 10~15분 · 호스트 Bash.**

### 서랍은 크지만 책상이 너무 작은 상황
프로그램이 64 MiB 자료를 책상 위에 올리려고 합니다. 책상에 허용된 공간은 32 MiB뿐이면 일을 계속할 수 없겠죠? 이번 실습은 같은 프로그램을 좁은 책상과 넓은 책상에서 실행합니다.

| 실행 | 프로그램이 요청하는 자료 | 메모리 한도 | 예상 |
|---|---|---|---|
| 첫 번째 | 64 MiB | 32 MiB | 메모리 부족으로 작업 종료 |
| 두 번째 | 같은 64 MiB | 128 MiB | 요청 성공·정상 종료 |

Python 자체도 메모리를 사용하므로 자료 크기만큼의 한도만 주면 충분하다고 가정하지 않습니다. 큰 파일을 전부 메모리에 올리는 분석에서도 같은 원리가 적용됩니다.

### 따라 하기 · 비교 도구 실행
[메모리 실습 스크립트 내려받기](labs/memory-limit.sh)를 저장한 **호스트 Bash**에서 실행합니다. 저장소를 내려받았다면 labs 폴더의 파일을 사용합니다.
```bash
bash memory-limit.sh
```

<details markdown="1"><summary>명령 한 줄씩 해석하기</summary>

| 명령 또는 부분 | 하는 일 |
|---|---|
| <code>bash memory-limit.sh</code> | 뒤에 지정한 셸 스크립트 파일을 Bash로 실행합니다. 파일을 저장한 위치에서 실행해야 합니다. |

저장소 루트에서는 `bash labs/memory-limit.sh`로 실행합니다. 첫 실행은 Python 이미지 다운로드가 필요합니다. 컨테이너별 메모리만 작게 제한하며 PC 메모리를 채우는 작업은 하지 않습니다. 각 실행에는 CPU 0.25 한도와 30초 종료 장치를 두었습니다. 스크립트는 자신의 실습 컨테이너만 자동 정리합니다.

### 결과 읽기
| 결과 항목 | 뜻 | 예상 출력 |
|---|---|---|
| Requesting 64 MiB | 자료를 메모리에 올리려 함 | 두 경우에 모두 표시 |
| Allocation succeeded | 자료를 올리는 데 성공 | 128 MiB 한도에서 표시 |
| Exit code | 프로그램이 어떻게 끝났는지 | 실패는 0이 아님, 성공은 0 |
| OOMKilled | 메모리 부족으로 종료됐다는 컨테이너 상태 | 32 MiB는 true, 128 MiB는 false |

OOM은 Out Of Memory, 메모리 부족을 뜻합니다. 낮은 한도에서는 보통 종료 코드 137이 관찰될 수 있습니다. **137만으로 OOM이라고 단정하지 말고 OOMKilled와 로그를 함께 확인합니다.** 환경에 따라 예상과 다르면 한도 설정·로그·종료 상태를 함께 기록하고 비교합니다.

### 실제 검증에서 관찰한 예시
같은 PC에서 64 MiB를 요청한 결과입니다.

| 메모리 한도 | 관찰 |
|---|---|
| 32 MiB | 종료 코드 137, OOMKilled=true, 성공 메시지 없음 |
| 128 MiB | 할당 성공 메시지, 종료 코드 0, OOMKilled=false |

이 결과는 컨테이너별 한도 안에서 검증했습니다. 제한 없는 작업으로 PC 전체 메모리를 고갈시키지는 않았습니다.

### 바꿔 보기 · 해결 방법을 말로 선택하기
이 작업을 성공시키려면 어떤 방법이 있을까요?
- 필요한 메모리를 충분히 할당받아 한도를 조정한다.
- 프로그램이 지원하면 자료를 나누어 처리한다.
- 동시에 실행하는 작업 수를 줄여 전체 메모리 사용을 줄인다.

한도 조정은 해당 작업의 실패를 피하는 방법이지만, 서버 전체 여유를 확인하지 않고 무조건 늘리지는 않습니다. 여러 작업의 합산 사용량과 기관의 할당을 함께 고려합니다.

### 고쳐 보기와 설명하기
“디스크가 많이 남았으니 메모리 부족은 아니다”, “메모리 제한을 없애면 모두 안전해진다”는 설명을 고치세요.
<details markdown="1"><summary>쉬운 해설</summary>
디스크와 메모리는 서랍과 책상처럼 다릅니다. 메모리 제한 없이 큰 작업을 실행하면 가용 메모리를 많이 사용해 다른 작업도 느려지거나 종료될 수 있습니다. 적절한 한도는 서버를 함께 쓰기 위한 장치지만, 내 프로그램에 필요한 메모리보다 너무 작으면 내 작업이 실패합니다. 필요한 양과 할당받은 양을 함께 확인합니다.
</details>

### CPU 예제와 비교해서 기억하기
CPU는 시간의 한도를 줄이면 계산이 느려질 수 있습니다. 메모리는 작업에 필요한 공간보다 작으면 느려지는 수준을 넘어 실패할 수 있습니다. 실제 상황에는 swap과 I/O도 영향을 줍니다. 이번 실습은 차이를 분명히 보기 위해 RAM 한도와 RAM+swap 한도를 같게 설정해 컨테이너의 swap 사용을 막습니다. 이 설정을 모든 실제 분석에 그대로 적용해야 한다는 뜻은 아닙니다.
