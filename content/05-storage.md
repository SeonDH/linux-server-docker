# 5. 서버 저장공간의 이해

> **실습 환경:** Linux 명령은 컨테이너, Docker 명령은 호스트
> **준비:** 0장 완료

**학습 목표:** 파일을 어느 경로에 저장하는지에 따라 사용하는 저장공간이 달라집니다.

## 작은 서랍과 큰 창고가 함께 있는 서버
서버의 루트 파일시스템 `/`를 기본 서랍, 별도 대용량 스토리지를 큰 창고로 생각해 보세요. 큰 창고가 있어도 계속 작은 서랍에 물건을 넣으면 서랍은 가득 찹니다.

별도 저장공간을 `/data` 같은 경로에 연결하는 것을 마운트라고 합니다. 이름이 /data인 폴더를 만들었다고 창고가 연결되는 것은 아닙니다. 이번 수업에서는 실제 디스크를 분할하거나 NAS를 새로 연결하지 않습니다. 작은 임시 공간을 연결하는 관찰 실습으로 저장 위치와 용량의 관계를 확인합니다.

## [실습] 따라 하기 · 전체 공간과 내 폴더의 크기
**실습 환경: course-linux 컨테이너.**
```bash
cd "$HOME/linux-server-lab"
df -h .
du -sh input output logs scratch
```

<details markdown="1"><summary>명령 한 줄씩 해석하기</summary>

| 명령 또는 부분 | 하는 일 |
|---|---|
| <code>cd &quot;$HOME/linux-server-lab&quot;</code> | 뒤의 경로로 현재 작업 위치를 옮깁니다. `$HOME`은 현재 환경의 홈, `..`는 한 단계 위 폴더입니다. |
| <code>df -h .</code> | 지정한 경로가 사용하는 파일시스템의 상태를 봅니다. `-h`는 전체·사용·남은 용량, `-i`는 파일·폴더를 관리하는 inode의 전체·남은 개수를 보여줍니다. |
| <code>du -sh input output logs scratch</code> | 지정한 폴더나 파일이 차지하는 공간을 봅니다. `-s`는 각 대상의 합계, `-h`는 읽기 쉬운 단위입니다. |
| `$HOME` | 현재 셸 환경의 홈 폴더입니다. 호스트와 컨테이너에서 다른 경로일 수 있습니다. |

</details>

| 명령 | 질문 |
|---|---|
| df -h . | 지금 저장하는 공간 전체에 얼마나 남았나요? |
| du -sh 폴더 | 이 폴더가 얼마나 사용하나요? |

컨테이너가 보는 공간이므로 실제 서버 구성과 다를 수 있습니다. 출력 숫자를 외우기보다 **“전체 여유와 폴더 사용량은 다르다”**는 것을 이해하세요.

## 사례 · 입력만 창고에 두면 충분할까요?
| 대상 | 예시 위치 | 어디에 쌓이나요? |
|---|---|---|
| 입력 데이터 | /data/user/input | 별도 스토리지에 연결됐다면 그곳 |
| 결과와 임시 파일 | 실행 옵션에 따른 경로 | 실제로 지정한 위치 |
| Docker 이미지·컨테이너 데이터·로그 | 엔진의 저장 설정 | 입력 폴더와 별개 |

입력을 큰 창고에 두어도 Docker 이미지와 로그가 자동으로 옮겨지지 않습니다. 이것이 기존 교육 서버에서 루트 공간이 부족해질 수 있었던 이유입니다.

## [실습] 따라 하기 · Docker가 보관하는 데이터 보기
**호스트 Bash에서 실행합니다.** 컨테이너 안이라면 exit로 나옵니다.
```bash
docker system df
```

<details markdown="1"><summary>명령 한 줄씩 해석하기</summary>

| 명령 또는 부분 | 하는 일 |
|---|---|
| <code>docker system df</code> | 이미지·컨테이너·볼륨·빌드 캐시의 공간 사용을 보여줍니다. `-v`는 자세한 내역입니다. |

</details>

이미지·컨테이너·볼륨 등의 사용량을 봅니다. 이것만으로 로그를 포함한 모든 디스크 사용량을 설명하지는 못합니다. 자세한 위치·로그 설정은 [선택 자료](deep-dive.html)에 있습니다.

## [실습] 작은 공간에서는 실패하고 큰 공간에서는 성공하기

같은 12MiB 파일을 8MiB 공간과 32MiB 공간에 써 봅니다. 작은 공간은 `No space left on device`로 실패하지만 큰 공간은 성공합니다. 실제 디스크를 채우지 않고 RAM 기반 임시 공간으로 재현합니다.

[저장 위치에 따른 공간 부족 실습 - 15분](practice-storage-paths.html)

## 공간이 부족하면 어떻게 할까요?
먼저 어디가 찼는지 확인합니다. 다음으로 내 파일의 용도와 보존 여부를 확인합니다. 공용 데이터·타인의 작업·Docker 저장 폴더를 함부로 삭제하지 않습니다. 내가 판단하기 어려우면 경로와 오류를 기록해 관리자에게 요청합니다.

## [실습] 반복 활동 · 어디가 가득 찼는지 찾기
**15분 · 작은 파일 관찰과 사례 토론.**

### 바꿔 보기
앞 단계에서 호스트로 나왔다면 `docker start -ai course-linux`로 다시 들어옵니다. **course-linux 안**에서 실습용 로그 한 줄을 만들고 해당 폴더 크기를 확인하세요. 같은 파일이 있으면 덮어씁니다.
```bash
cd "$HOME/linux-server-lab"
printf 'small practice log\n' > logs/storage-practice.log
du -sh logs
```

<details markdown="1"><summary>명령 한 줄씩 해석하기</summary>

| 명령 또는 부분 | 하는 일 |
|---|---|
| <code>cd &quot;$HOME/linux-server-lab&quot;</code> | 뒤의 경로로 현재 작업 위치를 옮깁니다. `$HOME`은 현재 환경의 홈, `..`는 한 단계 위 폴더입니다. |
| <code>printf &#x27;small practice log\n&#x27; &gt; logs/storage-practice.log</code> | 지정한 형식으로 글자를 출력합니다. `\n`은 줄바꿈, `\t`는 탭, `%s`는 뒤에 전달한 값을 넣는 자리입니다. |
| <code>du -sh logs</code> | 지정한 폴더나 파일이 차지하는 공간을 봅니다. `-s`는 각 대상의 합계, `-h`는 읽기 쉬운 단위입니다. |
| `> 경로` | 표준 출력을 파일에 저장합니다. 파일을 만들거나 덮어쓰지만 상위 폴더까지 만들지는 않습니다. |
| `$HOME` | 현재 셸 환경의 홈 폴더입니다. 호스트와 컨테이너에서 다른 경로일 수 있습니다. |

</details>

이번에는 output 폴더의 크기를 확인하세요. 실제 디스크를 가득 채우지 않습니다.
<details markdown="1"><summary>[답지] 해설 보기</summary>
```bash
du -sh output
```

<details markdown="1"><summary>명령 한 줄씩 해석하기</summary>

| 명령 또는 부분 | 하는 일 |
|---|---|
| <code>du -sh output</code> | 지정한 폴더나 파일이 차지하는 공간을 봅니다. `-s`는 각 대상의 합계, `-h`는 읽기 쉬운 단위입니다. |

</details>

파일시스템 특성에 따라 크기는 달라집니다. 지정한 폴더의 사용량을 본다는 점이 핵심입니다.
</details>

### 고쳐 보기
아래는 **교육용 가상 사례**입니다. 실제 PC의 출력이 아닙니다.

| 경로 | 상황 |
|---|---|
| / | 작은 기본 저장공간, 99% 사용 |
| /data | 별도 큰 저장공간, 20% 사용 |
| 입력 | /data/user/input |
| Docker 데이터 | 루트 파일시스템 쪽에 저장 |

“/data가 남았으니 어디에나 계속 저장해도 된다”는 설명을 고치세요. 먼저 확인할 위치와 관리자에게 전달할 정보를 적습니다.
<details markdown="1"><summary>힌트 보기</summary>
큰 창고가 있어도 작은 서랍은 찰 수 있습니다. 입력·출력·Docker 데이터는 별개입니다.
</details>
<details markdown="1"><summary>[답지] 해설 보기</summary>
현재 결과·임시 파일·Docker 데이터가 사용하는 경로를 확인합니다. 어디가 찼는지 df로, 내 폴더가 얼마나 쓰는지 du로 봅니다. 경로와 오류를 기록하고 공용 데이터 정리는 관리자와 협의합니다. /data에 입력을 두었다고 이미지나 로그가 자동 이동하지 않습니다.
</details>

### 설명하기
짝에게 “대용량 스토리지가 남아 있어도 루트가 찰 수 있는 이유”를 서랍·창고 비유로 말하세요.

## 이 장의 정리

- 저장하는 경로에 따라 사용하는 파일시스템이 달라진다.
- 입력을 큰 스토리지에 두어도 Docker 데이터와 로그는 별도로 쌓일 수 있다.
