# 2. Docker와 컨테이너의 개념

> **실습 환경:** 호스트 Bash
> **준비:** Docker Desktop 실행

**학습 목표:** 이미지로 작업 공간을 만들고, 그 안에서 프로그램을 실행합니다.

## 명령을 전달했는데 왜 내 PC에서는 안 될까요?
셸 스크립트는 명령을 적어 둔 파일입니다. “Python으로 이 파일을 처리하세요”라고 적혀 있어도 내 PC에 Python과 필요한 도구가 없으면 실행되지 않습니다.

**스크립트는 할 일을 적고, 이미지는 필요한 도구와 파일을 준비합니다.** 스크립트는 컨테이너 안에서도 사용할 수 있습니다.

## 준비된 도구와 작업 자리를 떠올려 보세요
종이를 자르려면 가위와 자가 필요합니다. 장소를 바꿀 때마다 도구를 다시 준비하는 대신, 준비된 도구 구성을 사용해 작업 자리를 마련하는 것입니다.

| 용어 | 아주 쉽게 말하면 |
|---|---|
| 이미지 | 도구와 필요한 파일이 준비된 원본 |
| 컨테이너 | 그 이미지로 만든 개별 작업 공간 |
| 프로세스 | 작업 공간 안에서 실행 중인 프로그램 |

```text
준비된 이미지 하나
    ├─ 컨테이너 A: 파일의 줄 수 세기
    └─ 컨테이너 B: 다른 파일 정렬하기
```
같은 이미지로 여러 작업 공간을 만들 수 있습니다. A에서 만든 내부 파일이 B에 자동으로 생기지는 않습니다. 컨테이너가 CPU·메모리를 새로 만드는 것도 아닙니다. 실제 PC의 자원을 사용합니다.

## 작업 공간을 치우면 결과는 어디에 남을까요?
컨테이너 안에만 결과를 두고 컨테이너를 삭제하면 그 결과도 사라집니다. 중요한 결과는 별도 보관함에 남깁니다.

| 용어 | 결과를 보관하는 방법 |
|---|---|
| bind mount | 내가 지정한 PC 폴더를 컨테이너에 연결 |
| 볼륨, volume | Docker가 관리하는 별도 저장공간을 연결 |

7장에서 PC 폴더에 결과를 남겨 봅니다. 지금은 **“작업하는 곳과 결과 보관하는 곳을 구분한다”**는 것만 기억하세요.

## Docker Desktop과 docker 명령
Docker Engine은 작업을 실행하는 관리자입니다. `docker` 명령은 관리자에게 요청하는 창구입니다. Docker Desktop은 PC에서 관리자와 Linux 실행 환경을 쉽게 준비해 주는 앱입니다.

```text
터미널의 docker 명령 → Docker Desktop의 엔진 → 컨테이너 실행
```
Linux 서버는 Engine을 직접 사용할 수 있어 Desktop이 필수는 아닙니다. Docker Hub는 이미지를 내려받는 곳입니다. Dockerfile은 이미지를 만드는 방법을 적은 설명서입니다. 지금 직접 작성할 필요는 없습니다.

## [실습] 따라 하기 · 인사 한 줄 출력하기
**실습 환경: 호스트 Bash.** 컨테이너 안이라면 먼저 `exit`로 나옵니다.
```bash
docker run --rm alpine:3.21 echo hello
```
**기대 결과:** `hello`

| 부분 | 뜻 |
|---|---|
| docker run | 새 작업 공간을 만들고 실행 |
| --rm | 끝나면 그 작업 공간을 자동 삭제 |
| alpine:3.21 | 사용할 이미지 |
| echo hello | 그 안에서 실행할 명령 |

이름 뒤 `:3.21`은 이미지를 구분하는 태그입니다. 이미지는 여전히 남습니다. 작업 공간은 종료 후 삭제됐습니다.

## 이미지와 컨테이너 확인하기
```bash
docker image ls
docker ps -a
```
첫 명령은 준비된 이미지, 두 번째는 남아 있는 컨테이너를 보여줍니다. 위 hello 컨테이너는 --rm으로 삭제돼 목록에 없습니다. 0장의 course-linux는 별도로 남아 있을 수 있습니다.

**정지**는 작업이 멈춘 상태, **삭제**는 그 작업 공간을 없애는 것입니다. 정지한 컨테이너의 내부 파일은 남을 수 있지만 삭제하면 사라집니다.

## [실습] 반복 연습 · 이미지와 작업 공간 구분하기
**15분 · 호스트 Bash.** 앞의 hello 출력이 성공한 다음 진행합니다.

### 바꿔 보기
앞의 명령에서 인사를 `hello-again`으로 바꿔 실행하세요. 이미지 이름은 그대로 둡니다.
<details markdown="1"><summary>힌트 보기</summary>
바꿀 부분은 실행할 명령인 `echo hello`입니다.
</details>
<details markdown="1"><summary>[답지] 해설 보기</summary>
```bash
docker run --rm alpine:3.21 echo hello-again
```
출력은 hello-again입니다. 같은 이미지로 새로운 작업을 실행했습니다.
</details>

### 고쳐 보기
“hello가 목록에 없으니 이미지도 삭제됐다”라는 설명은 맞을까요? 다음 목록을 비교해 잘못된 설명을 고치세요.
```bash
docker image ls
docker ps -a
```
<details markdown="1"><summary>힌트 보기</summary>
이미지와 컨테이너는 서로 다른 대상입니다. --rm은 어느 것을 지우나요?
</details>
<details markdown="1"><summary>[답지] 해설 보기</summary>
--rm은 종료된 해당 컨테이너를 삭제합니다. alpine:3.21 이미지는 목록에 남아 있습니다. 준비된 원본과 개별 작업 공간을 구분합니다.
</details>

### 설명하기
“이미지 하나로 hello와 hello-again을 실행했다”는 일을 준비된 도구와 작업 자리 비유로 설명하세요.

## 확인 질문
이미지를 내려받기만 하면 작업이 실행되나요? 컨테이너를 지우면 이미지도 같이 없어지나요?
<details><summary>[답지] 해설 보기</summary>
이미지는 도구를 준비한 것입니다. 실행할 작업 공간을 만들어야 일을 시작합니다. 컨테이너를 삭제해도 원본 이미지는 별도로 남습니다.
</details>

참고: [Docker 공식 개념 설명](https://docs.docker.com/get-started/docker-overview/). 자세한 Dockerfile·볼륨 설명은 [선택 자료](deep-dive.html)에서 읽으세요.

## 이 장의 정리

- 이미지는 준비된 원본, 컨테이너는 개별 작업 공간이다.
- 중요한 결과는 연결한 폴더 또는 별도 저장공간에 남긴다.
