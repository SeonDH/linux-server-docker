# 9. Singularity와 Apptainer의 이해

> **실습 환경:** 이론·비교 활동, 설치 불필요
> **준비:** 2장의 이미지·컨테이너 개념

**이론·비교 학습 · 목표:** Docker에서 배운 이미지·컨테이너·파일 연결 개념을 연구 서버의 컨테이너 도구와 연결합니다. 이 장에서는 설치와 실행 실습을 하지 않습니다.

## 먼저 비유로 이해하기: 준비된 도구로 작업하기
종이의 길이를 재는 작업을 한다고 생각해 보세요. 자와 가위가 필요합니다. 그런데 장소를 옮길 때마다 도구를 다시 구하고 준비하면 번거롭습니다. 컴퓨터에서도 분석 프로그램과 라이브러리를 매번 설치하면 같은 어려움이 생깁니다.

컨테이너 도구는 **필요한 도구가 준비된 환경으로 작업을 시작하도록 돕습니다.** Docker와 Singularity/Apptainer 모두 이 목적을 가집니다.

| 비유 속 대상 | 컴퓨터에서의 대상 |
|---|---|
| 자·가위가 준비된 도구 구성의 원본 | 이미지: 프로그램과 필요한 파일이 준비된 원본 |
| 그 구성을 사용해 마련한 작업 자리 | 컨테이너 실행 환경 |
| 작업 자리에서 실제로 자르는 일 | 실행 중인 프로그램·프로세스 |
| 잘라야 할 종이 | 입력 데이터 |
| 완성품을 따로 보관하는 서랍 | 연결한 결과 폴더 또는 저장공간 |
| 작업자를 위한 자리와 책상 공간 | CPU와 메모리 자원 |

비유의 핵심은 **도구 준비, 작업 실행, 결과 보관은 서로 다른 일**이라는 점입니다. 이미지는 물리 도구 상자가 아니라 실행 환경을 담은 것이며, CPU와 메모리는 실제 PC·서버의 자원을 사용합니다.

### Docker: 관리자가 작업 자리를 만들어 주는 방식
Docker Engine을 작업실 관리자라고 생각해 보세요. 우리는 “이 도구 구성으로 작업 자리를 만들어 주세요”라고 요청합니다. 관리자는 요청에 따라 컨테이너를 만들고 실행 상태를 관리합니다.

Docker Desktop은 개인 PC에서 이 관리자와 작업 환경을 쉽게 준비해 주는 앱입니다. 터미널의 docker 명령은 관리자에게 요청을 보내는 창구에 해당합니다.

### Singularity/Apptainer: 준비된 도구 꾸러미를 지정해 연구실에서 사용하는 방식
연구실에 준비된 `분석도구.sif` 꾸러미를 가져왔다고 생각해 보세요. “이 꾸러미에 있는 도구로 내 파일을 처리하겠다”고 지정해 실행합니다. 기본적인 사용에서는 내가 가진 사용자 권한으로 작업하고, 연구실의 CPU·메모리 사용 규칙을 따릅니다.

Docker도 공유 서버에서 사용할 수 있고 Apptainer도 개인 Linux에서 사용할 수 있습니다. 이 비유는 특정 장소에만 사용할 수 있다는 뜻이 아니라, **Docker는 엔진에게 요청하는 흐름, Apptainer는 이미지 파일을 지정해 명령을 실행하는 흐름**을 이해하기 위한 것입니다.

### 둘 다 결과는 작업 자리 밖에 보관합니다
작업 자리를 정리할 때 완성품까지 버리면 안 되겠죠? 중요한 결과는 따로 연결한 폴더에 남깁니다. Docker든 Apptainer든 입력·출력 경로와 보관 방법을 확인하는 이유는 같습니다.

### Linux는 도구를 사용할 수 있는 작업실입니다
어떤 장비는 정해진 시설에서만 사용할 수 있습니다. Singularity/Apptainer를 실행하는 데 필요한 작업실은 Linux 환경입니다. Windows에서는 WSL2로, macOS에서는 Linux VM 등으로 그 환경을 추가 준비할 수 있습니다.

이번 수업에서는 새 작업실을 준비하지 않고 **도구와 사용 방식만 비교**합니다. 설치 명령이나 SIF 실행을 따라 하지 않아도 됩니다.

## 도구 이름과 준비 환경
SingularityCE와 Apptainer는 공통 역사를 가진 별도 프로젝트입니다. 연구실에서 어떤 도구와 버전을 쓰는지 확인하면 됩니다. 이 수업에서는 명령 이름을 외우지 않습니다.

실제로 실행하려면 Linux와 별도 설치가 필요합니다. Windows는 WSL2, macOS는 Linux VM 등을 준비해야 하므로 이번에는 이론만 진행합니다. Docker Desktop만 설치하면 Apptainer도 실행되는 것은 아닙니다.

## 짧은 비교 활동 · 명령어 없이 설명하기
짝에게 다음 세 가지를 말해 보세요.

1. 준비된 도구 꾸러미는 무엇인가요? → 이미지
2. 실제로 작업하는 공간은 무엇인가요? → 컨테이너 실행 환경
3. 완성한 결과는 어디에 남길까요? → 별도로 연결한 결과 폴더

Docker는 엔진에게 작업 실행을 요청하고, Apptainer는 준비된 이미지 파일을 지정해 명령을 실행하는 흐름입니다. 둘 다 PC·서버의 CPU·메모리·디스크를 사용합니다.

## SIF는 이름만 알아 두세요
Apptainer에서는 실행 환경을 `.sif` 파일로 보관할 수 있습니다. 이 파일은 준비된 꾸러미이며 아직 실행 중인 작업은 아닙니다. 꾸러미를 가지고 있는 것과 실제로 작업하는 것은 다릅니다.

## 반복 비교 활동 · 실행하지 않고 설명하기
**5~10분 · 이론 활동, 설치 불필요.**

### 바꿔 보기
Docker의 작업실 관리자 비유를 “연구실에서 준비된 도구 꾸러미를 지정해 작업하는 Apptainer”로 바꿔 설명하세요. 둘 다 필요한 도구와 결과 보관 장소가 있다는 점을 찾습니다.

### 고쳐 보기
“Docker Desktop이 있으니 Apptainer도 바로 실행된다”, “SIF 파일이 있으니 분석이 이미 실행 중이다”는 말에서 잘못된 부분을 찾으세요.

### 설명하기
“도구가 달라도 경로·권한·자원을 확인해야 한다”는 이유를 한 문장으로 말하세요.
