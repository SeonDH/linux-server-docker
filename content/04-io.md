# 4. 파일 입출력과 파이프라인

> **실습 환경:** course-linux 컨테이너
> **준비:** 0장의 예제 파일

**학습 목표:** 화면에 보이는 결과와 오류는 서로 다른 통로로 나옵니다.

## 결과 통로와 오류 통로
정상 결과는 표준 출력, 문제를 알리는 메시지는 표준 오류로 나옵니다. `>`는 결과를 파일에 저장하고, `2>`는 오류를 파일에 저장합니다. `>`는 같은 파일이 있으면 덮어씁니다.

## [실습] 따라 하기 · 파일이 없는데 결과 파일은 생겼어요
**실습 환경: course-linux 컨테이너.**
```bash
cd "$HOME/linux-server-lab"
cat input/missing.tsv > output/result.txt 2> logs/error.log
echo "$?"
cat logs/error.log
wc -c output/result.txt
```

<details markdown="1"><summary>명령 한 줄씩 해석하기</summary>

| 명령 또는 부분 | 하는 일 |
|---|---|
| <code>cd &quot;$HOME/linux-server-lab&quot;</code> | 뒤의 경로로 현재 작업 위치를 옮깁니다. `$HOME`은 현재 환경의 홈, `..`는 한 단계 위 폴더입니다. |
| <code>cat input/missing.tsv &gt; output/result.txt 2&gt; logs/error.log</code> | 지정한 파일 내용을 읽어 출력합니다. `/`로 시작하면 절대 경로, `../`는 상위 폴더를 기준으로 찾습니다. |
| <code>echo &quot;$?&quot;</code> | 뒤의 글자나 변수 값을 출력합니다. `$?`는 바로 앞 명령의 종료 상태로, 보통 0은 성공·나머지는 실패입니다. |
| <code>cat logs/error.log</code> | 지정한 파일 내용을 읽어 출력합니다. `/`로 시작하면 절대 경로, `../`는 상위 폴더를 기준으로 찾습니다. |
| <code>wc -c output/result.txt</code> | 파일이나 입력의 크기를 셉니다. `-l`은 줄 수, `-c`는 바이트 수입니다. 파일이 만들어졌는지뿐 아니라 내용·크기도 확인합니다. |
| `2> 경로` | 오류 메시지를 해당 파일에 저장합니다. 같은 이름의 로그는 덮어씁니다. |
| `> 경로` | 표준 출력을 파일에 저장합니다. 파일을 만들거나 덮어쓰지만 상위 폴더까지 만들지는 않습니다. |
| `$HOME` | 현재 셸 환경의 홈 폴더입니다. 호스트와 컨테이너에서 다른 경로일 수 있습니다. |
| 예상된 실패 예제 | 일부러 없는 파일·잘못된 경로·빠진 따옴표 등을 사용했습니다. 해당 사례의 오류와 해결 단계까지 확인합니다. |

</details>

missing.tsv는 없는 파일입니다. 오류 로그에 이유가 남고 result.txt는 0바이트일 수 있습니다. 결과 파일이 생겼다는 사실만으로 성공한 것은 아닙니다.

`$?`는 바로 앞 명령의 종료 상태입니다. 보통 0은 성공, 0이 아닌 값은 실패를 뜻합니다. 다른 명령을 실행하기 전에 확인하세요.

echo "$?"

|---|---|

| <code>echo &quot;$?&quot;</code> | 뒤의 글자나 변수 값을 출력합니다. `$?`는 바로 앞 명령의 종료 상태로, 보통 0은 성공·나머지는 실패입니다. |
| <code>cat output/result.txt</code> | 지정한 파일 내용을 읽어 출력합니다. `/`로 시작하면 절대 경로, `../`는 상위 폴더를 기준으로 찾습니다. |
| `2> 경로` | 오류 메시지를 해당 파일에 저장합니다. 같은 이름의 로그는 덮어씁니다. |
| `> 경로` | 표준 출력을 파일에 저장합니다. 파일을 만들거나 덮어쓰지만 상위 폴더까지 만들지는 않습니다. |

</details>

종료 상태 0과 예제 내용이 기대됩니다.

## 파이프는 앞 결과를 다음 명령에 전달합니다
`|`는 앞 명령의 결과를 다음 명령의 입력으로 연결합니다. 물을 다음 통으로 보내는 관처럼 생각해 보세요.
```bash
cat input/samples.tsv | wc -l
```

<details markdown="1"><summary>명령 한 줄씩 해석하기</summary>

| 명령 또는 부분 | 하는 일 |
|---|---|
| <code>cat input/samples.tsv &#124; wc -l</code> | 지정한 파일 내용을 읽어 출력합니다. `/`로 시작하면 절대 경로, `../`는 상위 폴더를 기준으로 찾습니다. |
| `|` | 앞 명령의 표준 출력을 뒤 명령의 입력으로 전달합니다. 오류 메시지는 자동으로 전달되지 않습니다. |
| `wc -l` | 입력 파일이나 전달받은 입력의 줄 수를 셉니다. 예제는 헤더를 포함해 4줄입니다. |

</details>

헤더까지 4줄입니다. 앞 명령은 파일을 읽고, 뒤 명령은 줄 수를 셉니다. 간단한 작업은 `wc -l input/samples.tsv`처럼 직접 할 수도 있습니다.

파이프 앞 단계가 실패해도 마지막 명령은 성공할 수 있습니다. Bash에서 `set -o pipefail`을 설정하면 앞 단계의 실패도 종료 상태에 반영할 수 있습니다. 자세한 비교는 [선택 자료](deep-dive.html)에 있습니다.

## [실습] 긴 로그의 마지막 부분 보기 - 5분
**실습 환경: course-linux 컨테이너.** 큰 파일을 모두 화면에 출력하는 대신 마지막 몇 줄부터 확인한다.
```bash
cd "$HOME/linux-server-lab"
printf 'start\nreading input\nfinished\n' > logs/read-demo.log
tail -n 2 logs/read-demo.log
```

<details markdown="1"><summary>명령 한 줄씩 해석하기</summary>

| 명령 또는 부분 | 하는 일 |
|---|---|
| <code>cd &quot;$HOME/linux-server-lab&quot;</code> | 뒤의 경로로 현재 작업 위치를 옮깁니다. `$HOME`은 현재 환경의 홈, `..`는 한 단계 위 폴더입니다. |
| <code>printf &#x27;start\nreading input\nfinished\n&#x27; &gt; logs/read-demo.log</code> | 지정한 형식으로 글자를 출력합니다. `\n`은 줄바꿈, `\t`는 탭, `%s`는 뒤에 전달한 값을 넣는 자리입니다. |
| <code>tail -n 2 logs/read-demo.log</code> | 파일의 마지막 부분을 봅니다. `-n 2`는 마지막 두 줄, `-f`는 새로 추가되는 내용을 계속 보여줍니다. `-f` 관찰은 Ctrl+C로 끝냅니다. |
| `> 경로` | 표준 출력을 파일에 저장합니다. 파일을 만들거나 덮어쓰지만 상위 폴더까지 만들지는 않습니다. |
| `$HOME` | 현재 셸 환경의 홈 폴더입니다. 호스트와 컨테이너에서 다른 경로일 수 있습니다. |

</details>

reading input과 finished가 기대 결과다. 실제 업무에서는 원문 오류가 있는지 확인하며, finished라는 문구만으로 결과 내용까지 검증됐다고 판단하지 않는다.

## 이 장의 정리

- 결과 파일이 있어도 명령이 실패했을 수 있다.
- 종료 상태와 오류 로그를 함께 확인한다.
