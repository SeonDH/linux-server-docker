실습 환경: 호스트 Bash 준비: Docker Desktop 실행

학습 목표: 이미지로 작업 공간을 만들고, 그 안에서 프로그램을 실행합니다.

작업 설명서가 있어도 가위가 없으면 자를 수 없어요

종이를 10cm 길이로 자르려고 합니다. 다음과 같은 작업 설명서를 준비했습니다.

1. 자로 10cm를 잽니다.
2. 종이에 선을 긋습니다.
3. 가위로 선을 따라 자릅니다.

설명서는 잘 적혀 있습니다. 그런데 내 책상에 가위와 자가 없다면 어떨까요? 설명서만으로는 종이를 자를 수 없습니다.

컴퓨터에서도 비슷한 일이 생깁니다. 셸 스크립트는 컴퓨터가 할 일을 순서대로 적어 둔 파일입니다. “Python으로 이 파일을 처리하세요”라고 적어 두었어도, 내 컴퓨터에 Python이나 필요한 프로그램이 없으면 실행되지 않습니다.

스크립트는 작업 설명서입니다. 설명서가 있다고 필요한 도구까지 생기는 것은 아닙니다.

Docker 이미지는 필요한 도구를 준비해 둔 작업 세트예요

다른 책상에서도 같은 작업을 하려면 가위와 자를 다시 찾아야 합니다. 가위의 종류나 자의 눈금이 달라서 작업하기 어려울 수도 있습니다.

그래서 필요한 가위와 자를 한 세트로 준비해 두고, 작업 설명서도 함께 넣어 둔다고 생각해 보세요. 새 작업 자리에서도 필요한 도구를 준비하기 쉬워집니다.

Docker 이미지도 이와 비슷합니다. 프로그램과 그 프로그램이 실행되는 데 필요한 파일·환경을 함께 준비해 둡니다. 작업 스크립트까지 이미지에 넣을 수도 있습니다.

종이 자르기 컴퓨터에서 하는 일
자를 종이 입력 데이터
종이를 자르는 작업 설명서 셸 스크립트
가위와 자 작업에 필요한 프로그램
도구를 준비해 둔 작업 세트 Docker 이미지
세트를 꺼내 실제로 작업하는 자리 컨테이너
잘라서 완성한 종이 출력 데이터, 즉 결과 파일

이미지에 작업 스크립트와 입력 데이터가 반드시 들어 있는 것은 아닙니다. 도구만 준비된 이미지에 내 스크립트와 데이터를 연결해서 사용할 수도 있습니다. 7장에서 내 컴퓨터의 파일을 연결해 봅니다.

컨테이너는 준비된 도구로 실제 작업하는 공간이에요

이미지를 내려받는 것은 작업 세트를 준비하는 단계입니다. 내려받기만 해서는 작업이 실행되지 않습니다.

그 이미지로 작업 공간을 만들고 프로그램을 실행하면 일을 시작합니다. 이 작업 공간이 컨테이너입니다. 그 안에서 실행 중인 프로그램은 프로세스라고 부릅니다.

이미지: 도구와 실행 환경을 준비해 둠
    ├─ 컨테이너 A: 첫 번째 파일로 작업
    └─ 컨테이너 B: 두 번째 파일로 작업

같은 이미지로 여러 컨테이너를 만들 수 있습니다. 같은 도구 구성을 사용하더라도 각자의 작업 공간은 따로 있습니다. A의 내부에 만든 파일이 B에 자동으로 생기지는 않습니다.

작업 자리를 여러 개 만든다고 책상의 크기가 늘어나지는 않습니다. 컨테이너도 실제 컴퓨터의 CPU와 메모리를 함께 사용합니다.

이미지 = 준비된 작업 세트 / 컨테이너 = 그 세트로 실제 작업하는 공간

작업 공간을 치우기 전에 결과를 보관해요

작업을 마친 종이를 작업 자리에만 두고, 그 자리에 있는 것들을 모두 버리면 결과도 잃어버립니다. 보관할 종이는 별도 보관함에 넣어 두어야 합니다.

컨테이너도 마찬가지입니다. 컨테이너 내부에만 결과를 저장하고 컨테이너를 삭제하면 결과도 사라집니다. 중요한 결과는 컨테이너와 별도로 보관하도록 저장공간을 연결합니다.

방법 쉽게 설명하면
bind mount 내가 정한 컴퓨터 폴더를 작업 공간에서도 열어 쓰기
볼륨, volume Docker가 관리하는 별도 보관함을 작업 공간에 연결하기

예를 들어 내 컴퓨터의 output 폴더를 컨테이너에 연결하고 그곳에 결과를 쓰면, 컨테이너를 삭제해도 내 컴퓨터의 결과 파일은 남습니다. 파일을 연결하는 구체적인 방법은 7장에서 실습합니다.

지금은 “작업 공간은 지워도, 결과를 보관할 폴더는 남긴다”는 것만 기억하세요.

Docker Desktop과 docker 명령

Docker Engine은 작업을 실행하는 관리자입니다. docker 명령은 관리자에게 요청하는 창구입니다. Docker Desktop은 PC에서 관리자와 Linux 실행 환경을 쉽게 준비해 주는 앱입니다.

터미널의 docker 명령 → Docker Desktop의 엔진 → 컨테이너 실행

Linux 서버는 Engine을 직접 사용할 수 있어 Desktop이 필수는 아닙니다. Docker Hub는 이미지를 내려받는 곳입니다. Dockerfile은 이미지를 만드는 방법을 적은 설명서입니다. 지금 직접 작성할 필요는 없습니다.

[실습] 따라 하기 · 인사 한 줄 출력하기

실습 환경: 호스트 Bash. 컨테이너 안이라면 먼저 exit로 나옵니다.

docker run --rm alpine:3.21 echo hello

기대 결과: hello

여기서 alpine:3.21은 무엇인가요?

Alpine Linux는 필요한 기본 도구를 갖춘 작고 가벼운 리눅스입니다. alpine:3.21은 이 리눅스 환경을 준비해 둔 Docker 이미지입니다.

  • alpine: 사용할 이미지의 이름입니다.
  • 3.21: Alpine Linux 3.21 버전 계열을 지정하는 태그입니다. Docker 자체의 버전은 아닙니다.

앞의 비유로 말하면 기본 도구가 들어 있는 작은 작업 세트입니다. 이번 예제에서는 그 안에 있는 echo 명령으로 hello를 출력합니다. echo hello라는 작업은 이미지 이름 뒤에서 우리가 지정했습니다.

이 명령을 실행한다고 내 컴퓨터의 운영체제가 Alpine으로 바뀌지는 않습니다. 컨테이너 안에서 준비된 리눅스 도구를 사용하는 것입니다. 처음 실행할 때 이미지가 내 컴퓨터에 없으면 Docker가 내려받습니다.

참고: Alpine 공식 이미지.

부분 뜻
docker run 새 작업 공간을 만들고 실행
–rm 끝나면 그 작업 공간을 자동 삭제
alpine:3.21 사용할 이미지
echo hello 그 안에서 실행할 명령

이름 뒤 :3.21은 이미지를 구분하는 태그입니다. 이미지는 여전히 남습니다. 작업 공간은 종료 후 삭제됐습니다.

이미지와 컨테이너 확인하기

docker image ls
docker ps -a

첫 명령은 준비된 이미지, 두 번째는 남아 있는 컨테이너를 보여줍니다. 위 hello 컨테이너는 –rm으로 삭제돼 목록에 없습니다. 0장의 course-linux는 별도로 남아 있을 수 있습니다.

정지는 작업이 멈춘 상태, 삭제는 그 작업 공간을 없애는 것입니다. 정지한 컨테이너의 내부 파일은 남을 수 있지만 삭제하면 사라집니다.

15분 · 호스트 Bash. 앞의 hello 출력이 성공한 다음 진행합니다.

바꿔 보기

앞의 명령에서 인사를 hello-again으로 바꿔 실행하세요. 이미지 이름은 그대로 둡니다.

힌트 보기

바꿀 부분은 실행할 명령인 echo hello입니다.

[답지] 해설 보기 
docker run --rm alpine:3.21 echo hello-again

출력은 hello-again입니다. 같은 이미지로 새로운 작업을 실행했습니다.

고쳐 보기

“hello가 목록에 없으니 이미지도 삭제됐다”라는 설명은 맞을까요? 다음 목록을 비교해 잘못된 설명을 고치세요.

docker image ls
docker ps -a
힌트 보기

이미지와 컨테이너는 서로 다른 대상입니다. –rm은 어느 것을 지우나요?

[답지] 해설 보기

–rm은 종료된 해당 컨테이너를 삭제합니다. alpine:3.21 이미지는 목록에 남아 있습니다. 준비된 원본과 개별 작업 공간을 구분합니다.

설명하기

“이미지 하나로 hello와 hello-again을 실행했다”는 일을 작업 세트와 작업 자리 비유로 설명하세요. 같은 세트를 사용했지만 작업은 두 번 따로 실행했다는 점을 떠올려 보세요.

확인 질문

이미지를 내려받기만 하면 작업이 실행되나요? 컨테이너를 지우면 이미지도 같이 없어지나요?

[답지] 해설 보기 이미지는 도구를 준비한 것입니다. 실행할 작업 공간을 만들어야 일을 시작합니다. 컨테이너를 삭제해도 원본 이미지는 별도로 남습니다.

이 장의 정리

  • 스크립트는 작업 설명서이고, 필요한 프로그램은 따로 있어야 한다.
  • 이미지는 도구와 실행 환경을 준비한 작업 세트다.
  • 컨테이너는 그 이미지로 만들어 실제 작업하는 공간이다.
  • 중요한 결과는 연결한 폴더 또는 별도 저장공간에 남긴다.
