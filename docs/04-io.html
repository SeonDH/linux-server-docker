실습 환경: course-linux 컨테이너 준비: 0장의 예제 파일

학습 목표: 화면에 보이는 결과와 오류는 서로 다른 통로로 나옵니다.

결과 통로와 오류 통로

정상 결과는 표준 출력, 문제를 알리는 메시지는 표준 오류로 나옵니다. >는 결과를 파일에 저장하고, 2>는 오류를 파일에 저장합니다. >는 같은 파일이 있으면 덮어씁니다.

[실습] 따라 하기 · 파일이 없는데 결과 파일은 생겼어요

실습 환경: course-linux 컨테이너.

cd "$HOME/linux-server-lab"
cat input/missing.tsv > output/result.txt 2> logs/error.log
echo "$?"
cat logs/error.log
wc -c output/result.txt

missing.tsv는 없는 파일입니다. 오류 로그에 이유가 남고 result.txt는 0바이트일 수 있습니다. 결과 파일이 생겼다는 사실만으로 성공한 것은 아닙니다.

$?는 바로 앞 명령의 종료 상태입니다. 보통 0은 성공, 0이 아닌 값은 실패를 뜻합니다. 다른 명령을 실행하기 전에 확인하세요.

[실습] 따라 하기 · 올바른 파일로 다시 실행

cat input/samples.tsv > output/result.txt 2> logs/error.log
echo "$?"
cat output/result.txt

종료 상태 0과 예제 내용이 기대됩니다.

파이프는 앞 결과를 다음 명령에 전달합니다

|는 앞 명령의 결과를 다음 명령의 입력으로 연결합니다. 물을 다음 통으로 보내는 관처럼 생각해 보세요.

cat input/samples.tsv | wc -l

헤더까지 4줄입니다. 앞 명령은 파일을 읽고, 뒤 명령은 줄 수를 셉니다. 간단한 작업은 wc -l input/samples.tsv처럼 직접 할 수도 있습니다.

파이프 앞 단계가 실패해도 마지막 명령은 성공할 수 있습니다. Bash에서 set -o pipefail을 설정하면 앞 단계의 실패도 종료 상태에 반영할 수 있습니다. 자세한 비교는 선택 자료에 있습니다.

[실습] 반복 연습 · 결과와 오류를 직접 구분하기

15~20분 · course-linux 컨테이너.

바꿔 보기

예제 파일을 output/repeat-result.txt에 저장하고, 오류는 logs/repeat-error.log에 저장하세요. 앞 실습의 결과·로그 이름만 바꿉니다.

힌트 보기

정상 결과는 > 뒤, 오류는 2> 뒤의 경로입니다.

[답지] 해설 보기 
cd "$HOME/linux-server-lab"
cat input/samples.tsv > output/repeat-result.txt 2> logs/repeat-error.log
echo "$?"
cat output/repeat-result.txt

종료 상태 0, 예제 내용 4줄이 기대됩니다. 정상 실행에서는 오류 로그가 비어 있을 수 있습니다.

고쳐 보기

다음 파이프는 없는 파일을 읽습니다. “0줄이 나왔으니 성공”이라고 판단해도 될까요?

set +o pipefail
cat input/missing.tsv 2> logs/repeat-pipe.log | wc -l
echo "$?"
cat logs/repeat-pipe.log

실제로 존재하는 입력으로 고치고 4줄이 나오는지 확인하세요.

힌트 보기

마지막 wc는 읽은 줄이 없어도 성공할 수 있습니다. 오류 로그와 파일 이름을 확인하세요.

[답지] 해설 보기 
cat input/samples.tsv | wc -l

4줄이 기대됩니다. 앞의 실패 사례는 기본 설정에서 마지막 명령의 성공만 반영할 수 있습니다. 다음도 비교하세요.

set -o pipefail
cat input/missing.tsv 2> logs/repeat-pipe.log | wc -l
echo "$?"

이제 종료 상태는 0이 아닙니다. 숫자를 외우지 말고 로그와 함께 실패를 확인합니다. 비교를 마치면 아래 명령으로 이 실습 전의 기본 설정으로 돌아갑니다.

set +o pipefail

설명하기

“파일이 생겼다”, “숫자가 출력됐다”는 사실만으로 성공을 판단할 수 없는 이유를 말해 보세요.

확인 질문

빈 결과 파일을 만나면 어디를 확인할까요?

[답지] 해설 보기 실행 직후의 종료 상태와 오류 로그를 확인합니다. 입력 경로가 맞는지부터 봅니다.

[실습] 긴 로그의 마지막 부분 보기 - 5분

실습 환경: course-linux 컨테이너. 큰 파일을 모두 화면에 출력하는 대신 마지막 몇 줄부터 확인한다.

cd "$HOME/linux-server-lab"
printf 'start\nreading input\nfinished\n' > logs/read-demo.log
tail -n 2 logs/read-demo.log

reading input과 finished가 기대 결과다. 실제 업무에서는 원문 오류가 있는지 확인하며, finished라는 문구만으로 결과 내용까지 검증됐다고 판단하지 않는다.

이 장의 정리

  • 결과 파일이 있어도 명령이 실패했을 수 있다.
  • 종료 상태와 오류 로그를 함께 확인한다.
