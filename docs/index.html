## 교육 대상과 학습 목적 명령어를 배웠지만 “왜 쓰는지”, “어디에서 실행하는지”가 아직 헷갈리는 분을 위한 보충 교재입니다. 설명을 쉬운 비유로 읽고, 짧은 실습을 성공한 뒤 한 가지를 바꾸고 작은 오류를 고쳐 봅니다. 모든 명령과 옵션을 외울 필요는 없습니다.

교재 사용 안내에서 실행 환경을 먼저 확인하고, 헷갈리는 말은 핵심 용어에서 찾아본다.

목차

장 오늘 이해할 것 작은 실습
0 사전 준비 Docker 설치와 공통 실습 환경 설치·실행 확인
1 컴퓨터 자원 CPU·메모리·디스크는 다르다 자원 상태 보기
2 쉬운 Docker 개념 이미지와 컨테이너는 다르다 hello 출력
3 경로와 권한 파일 주소와 사용 허가 경로·실행 권한 확인
4 결과와 오류 결과 파일만으로 성공을 판단하지 않는다 오류 로그 읽기
5 저장공간 큰 디스크가 있어도 저장 위치가 중요하다 df·du 관찰
6 내 작업 관리 내 작업을 확인하고 종료한다 PID·docker stats 확인
7 파일 연결 컨테이너 결과를 PC에 남긴다 줄 수 결과 저장
8 오류 해결 연습 오류 → 확인 → 수정 → 재실행 Linux·Docker 오류·종합 미션
9 Singularity 이해 다른 컨테이너 도구도 목적은 비슷하다 비유로 비교·이론만

반복 학습 방법

따라 하기 → 바꿔 보기 → 고쳐 보기 → 설명하기 순서로 진행합니다. 따라 하기에서는 예제 명령을 실행하고, 바꿔 보기와 고쳐 보기에서는 직접 시도합니다. 막히면 접힌 힌트를 먼저 보고 해설은 그다음 확인합니다. 자원·저장공간·Singularity는 관찰과 비교 활동을 섞어 진행합니다.

각 단계가 처음부터 빨리 끝나지 않아도 괜찮습니다. 성공한 결과와 이유를 설명하는 것이 목표입니다.

어디에서 실행하나요?

각 실습 맨 위의 실행 위치를 읽으세요. Linux 명령은 course-linux 안, Docker 명령은 PC의 호스트 Bash입니다. 0장에서 준비한 폴더와 작은 예제 파일을 계속 사용합니다. 9장은 별도 설치 없이 이론만 진행합니다.

[실습] 자원·저장공간 비교

  • Docker CPU·메모리 관찰 - 20분
  • CPU 공유와 자원 제한 - 20분
  • 메모리 부족과 오류 확인 - 15분
  • 저장 위치에 따른 공간 부족 - 15분

5·6장에서 실습을 안내하고 별도 페이지에서 따라 한다. 실제 검증한 예시 숫자와 교육생 PC의 결과는 다를 수 있다.

기본 학습과 선택 학습

이 페이지의 1~9장이 기본 경로입니다. 어려운 진단·파이프 설정·자원 제한·Dockerfile·볼륨 실습은 더 알고 싶을 때로 옮겼습니다. 처음부터 읽거나 모두 따라 하지 않아도 됩니다.

기본 학습을 마친 뒤 필요한 추가 실습을 선택하세요. 진도보다 결과와 이유를 이해하는 데 충분한 시간을 쓰세요.
