[실습] CPU 공유와 자원 제한 - 20분

이 페이지 목차
  • 함께 쓰는 CPU 실습 · 내 제한이 다른 작업에 주는 영향

실습 환경: 호스트 Bash. Windows는 WSL Ubuntu, macOS는 터미널에서 실행한다. 준비: Docker Desktop 실행 및 0장 완료.

함께 쓰는 CPU 실습 · 내 제한이 다른 작업에 주는 영향

비교 실습 · 15~20분 · 호스트 Bash.

작업자 두 명이 계산기 하나를 나눠 쓰는 상황

계산기 하나를 A와 B가 번갈아 쓴다고 생각해 보세요. A가 사용할 시간을 제한하면 A의 일은 늦게 끝날 수 있지만 B가 사용할 시간이 더 생길 수 있습니다.

이 실습은 가상의 내 작업 A와 동료 작업 B가 같은 CPU 하나를 공유하게 합니다. 실제 다른 사람의 작업을 건드리지 않고 개인 PC의 컨테이너 두 개로 상황을 만듭니다.

실행 내 작업 A 동료 역할 B 공통 조건
첫 번째 CPU 사용 시간 한도 없음 CPU 사용 시간 한도 없음 같은 가상 CPU 하나에서 같은 계산
두 번째 CPU 한도 0.25 CPU 사용 시간 한도 없음 같은 계산과 같은 CPU

두 경우 모두 메모리는 128 MiB로 제한합니다. 프로그램은 각각 같은 횟수의 계산을 하고 완료 시간만 비교합니다. 90초 제한으로 자동 종료하며, 스크립트가 자신이 만든 컨테이너를 정리합니다. 다른 PC 작업의 상태·성능에 따라 수치는 달라집니다.

1. 따라 하기 · 비교 도구 실행

실습 스크립트 내려받기를 저장합니다. Windows는 그 파일을 WSL Ubuntu에서 접근할 수 있는 곳으로 옮깁니다. 교재 저장소를 내려받았다면 labs/cpu-sharing.sh를 사용하면 됩니다. 스크립트가 있는 폴더의 호스트 Bash에서 실행하세요.

bash cpu-sharing.sh

저장소 루트에서는 bash labs/cpu-sharing.sh로 실행합니다. 첫 실행은 Python 이미지를 내려받으므로 인터넷과 시간이 필요합니다. 코드를 외울 필요는 없습니다. 실행하면 [1/2] CPU 사용 시간 제한 없음, [2/2] 내 작업 A만 CPU 25% 제한이 표시됩니다. 스크립트가 Docker의 실제 한도 설정을 조회해 각 작업의 제한 여부를 출력하고, 마지막에 두 실행의 완료 시간을 한국어 표로 비교합니다. 숫자는 직접 관찰한 결과이며 PC마다 다릅니다.

2. 기록하기

관찰 A 완료 시간 B 완료 시간
[1/2] 둘 다 CPU 시간 한도 없음 직접 기록 직접 기록
[2/2] A만 CPU 25% 제한 직접 기록 직접 기록

기대하는 경향은 A가 느려지고 B가 더 빨리 끝나는 것입니다. 숫자가 항상 같은 것은 아닙니다. 차이가 작다면 다른 PC 작업, 가상화 환경, 측정 변동을 확인하고 한 번 더 비교해 보세요. 무조건 같은 결과가 나와야 하는 정답 실험은 아닙니다.

실제 검증에서 관찰한 예시

2026-10-03 Intel Mac의 Docker Desktop에서 관찰한 한 번의 결과입니다. 교육생 PC의 정답 수치가 아닙니다.

실행 A 완료 시간 B 완료 시간
둘 다 CPU 시간 한도 없음 6.07초 5.79초
A만 0.25 CPU 한도 14.13초 4.09초

A는 늦게 끝났고 B는 더 일찍 끝났습니다. 같은 CPU를 공유하는 이 예제에서 내 제한이 다른 작업의 경쟁을 줄이는 효과를 보여줍니다. 다른 자원의 영향이 모두 사라졌다는 뜻은 아닙니다.

3. 설명하기

A와 B는 같은 일을 했는데 완료 시간이 달라진 이유를 “계산기 사용 시간”으로 설명하세요. 단순히 빠르다·느리다 대신, 내 자원 제한으로 다른 작업이 사용할 여지를 남겼다는 점을 말합니다.

반드시 함께 이해할 점

CPU 제한은 영향을 줄이는 방법이며 다른 사용자에게 영향이 전혀 없다는 보장은 아닙니다. 메모리·디스크 I/O·공유 저장공간·네트워크도 서로 영향을 줍니다. 여러 컨테이너가 각각 제한을 지켜도 합산 사용량은 커질 수 있습니다. CPU 제한으로 모든 작업이 느려지는 것도 아닙니다. CPU 계산이 병목인 이번 예제에서 차이를 관찰합니다.

실제 서버에서는 도구 스레드 수, 메모리 사용량, 입력·출력 위치, 스케줄러의 자원 할당도 함께 지킵니다. 이 실습의 –cpuset-cpus=0은 비교를 위해 두 작업을 같은 논리 CPU에 배치하는 장치이며 실제 서버에 그대로 따라 적용할 기본 권장 설정은 아닙니다.
